# 핸드오프 — AI Agent 프로토타입 (2026-07-19)

## 오늘 이해한 것 (개념)

- 요청 1건 = Gemini 2회 호출: 1차(tool 선택·지시) → 앱이 tool 실행 → 2차(결과로 자연어 생성)
- `@Tool` 메서드는 직접 호출하는 코드가 없음 — Spring AI가 description 기반으로 리플렉션 호출. Gemini는 이름+description+파라미터 스키마만 봄
- `defaultTools/defaultSystem/defaultAdvisors` = 전역 기본값, `prompt()` 체인의 `.tools()` = 요청 한정 추가
- `resolveConversationId`: conversationId 없으면 UUID 발급 (`df3a2d8f...`가 그것)
- Gemini에게 tool 결과 JSON은 순회 대상이 아니라 재해석하는 텍스트 → 목록 누락 규칙의 이유

> 위 개념들은 안정화되면 `concepts/spring-ai-tool-calling.md`, `concepts/gemini-2call-flow.md`로 증류 예정
