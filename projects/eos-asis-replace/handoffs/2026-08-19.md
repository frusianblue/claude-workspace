# 핸드오프 — MAR/EOS AS-IS 치환 도구 (2026-08-19)

`2026-08-18b.md`의 `next`를 그대로 실행한 세션.
**Find-AsisPath 스캔 경로의 PS 5.1 런타임 검증을 처음으로 통과**했고, 이어서 A-1 → A-2 연결까지 확인했다.
A축(경로/IP 치환 도구)은 이걸로 **더 갈 데가 없다** — 남은 건 도구가 아니라 매핑표 내용이다.

## 오늘 확정한 것

### 1. Find-AsisPath v9.8 — 5.1 스캔 경로 런타임 검증 통과

`New-FindTestFixture` 픽스처로 실행. **기대값 29건과 전 항목 일치.**

```
.\New-FindTestFixture.ps1 -Force
.\Find-AsisPath.ps1 -Root ".\fixtures\findtest" -Kind all -Drives "d,w,x,y,z,t" -Hosts "WDAAD11,WDDIM11"
```

| 항목 | 기대 | 실측 |
|---|---|---|
| 총 건수 | 29 | 29 |
| Kind별 | path 8 / unc 8 / port 5 / ip 4 / domain 3 / host 1 | 동일 |
| FoundIn별 | FILE 23 / CLASS 3 / JAR 3 | 동일 |
| Container | eos-common-1.0.jar 3 | 동일 |
| Category | java 15 / resources 8 / classes 3 / lib 3 | 동일 |
| `_skipped.dat` | jar 1 / domain 1 / ip 1 | 3행 전부 |
| N01~N15 + C04 | 0건 | 0건 |

**8/18 1차 핸드오프 미해결 1번이 완전히 닫혔다.** `-Inventory`는 `if ($Inventory) { ... return }`으로
조기 반환하므로 정규식 조립부와 `Kind`/`Target`/`Value` 컬럼 생성부가 한 줄도 실행되지 않았는데,
이번에 그 구간이 5.1에서 처음 돌았다. 오탐 15종(`\d{1,3}` / `forward:/` / `2.3.4.726` / `12:30` /
`-//W3C//DTD` / `javax.net.ssl` / `java.io`)과 상수풀 길이바이트 `0x2F` 가스(C04)가 전부 걸러졌다.

### 2. Extract-MappingDraft v2.1 — A-1 리포트 소비 확인

같은 리포트로 `-Mode Path -ConsoleOnly`. **11건 + 드라이브 루트 단독 2건(`t:` `z:`)** 산출.
`Kind`/`Value` 컬럼이 실제로 매핑표 재료가 된다는 것이 확인됐다.

### 3. `-Depth` 기본값이 2다 — 하위 경로가 접힌다

예측과 실측이 딱 한 줄 어긋났다.

| 예측 | 실측 |
|---|---|
| `d:/app/ant/old` | **`d:/app/ant`** |

`Get-NormalizedPath`의 `$Depth` 기본값이 **0이 아니라 2**였다. 세그먼트 4개(`d:`,`app`,`ant`,`old`)라
`segs[0..2]`로 잘렸고, 세그먼트 3개인 `d:/eos/upload`·`y:/wormsdata15/upload`는 그대로 살았다.
**로직은 정상, 가정이 틀렸다.**

접두사 치환용 매핑표라면 절단이 보통 맞는 방향이지만, **서로 다른 하위 경로가 한 줄로 뭉개지는 경우**가 위험하다.

```
d:\app\ant\old  ─┐
                 ├─→ 둘 다 d:/app/ant 한 줄로 접힘 → TO-BE에서 갈라낼 수 없다
d:\app\ant\new  ─┘
```

폐쇄망 소스엔 `lib\v1` / `lib\v2` 같은 버전 폴더가 흔하므로 실제로 밟을 수 있다.
**대응: 실소스에서 `-Depth 2`와 `-Depth 0`을 각각 뽑아 건수 차이를 본다.** 차이 나는 만큼 접힌 것이다.

### 4. Find가 잡지 '않는' 것 3가지 — 설계상 정상이나 운영 리스크

픽스처 대조에서 드러난 경계다. 버그가 아니라 **매핑표 작성 시 빠뜨리기 쉬운 지점**이다.

| 대상 | 잡히는 Kind | 안 잡히는 Kind | 리스크 |
|---|---|---|---|
| `\\10.10.18.229\image` | `unc` | `ip` | IP 매핑표만 만들면 이 IP는 안 바뀐다 |
| `\\nas01.company.co.kr\pub` | `unc` | `domain` | 도메인 인벤토리에서 NAS 호스트가 빠진다 |
| `Z:` / `T:` (변수 담김) | `path` | — | Extract가 RootOnly로 분리. **치환 불가, 수동 처리** |

중복 계상이 없는 건 좋지만, **한 값이 한 Kind에만 나타나므로 그 Kind의 매핑표를 안 만들면 조용히 누락된다.**
`Z:`/`T:`는 `Drive3 = "Z:"` 처럼 변수에 담겨 나중에 조립되는 형태라 치환 스크립트가 손댈 수 없다 —
`Get-MappedDrives` 결과(드라이브 → UNC)와 대조해 별도 수동 목록으로 관리할 것.

### 5. 확인만 하고 넘어간 것 (이상 없음)

`port`의 `Value` 형식이 3종 혼재(`:1521` / `tomcat.port=8080` / `server.port: 9090`)인데,
`Get-NormalizedPort`가 `(\d{1,5})\s*$`로 전부 흡수한다. **문제없음.**

### `New-FindTestFixture` v1/v1.1 구분 근거

헤더는 `신규 v1`인데 배너는 `v1.1`이라 어긋나 있었다. **LF 단독 줄이 패치 지점을 그대로 가리켰다** —
`$ascii` 선언(59행)과 `[J02]` 주의문(212~215행) 5줄만 LF였다. 둘 다 같은 발견(Find가 아카이브·`.class`를
`Encoding::ASCII`로 디코드)에서 나온 한 묶음이라 v1.1로 묶어 이력에 기록했다.

**코드 라인은 한 글자도 안 바뀌었다** — 주석 아닌 줄 전체를 비교해 동일 확인.

## 이어서 할 때 참고

- **`-Depth` 같은 파라미터 기본값은 배너/콘솔 출력으로 확인할 것.** 오늘 예측이 틀린 원인이
  로직이 아니라 기본값 가정이었다. Extract는 `Depth=2`를 배너에 찍어줘서 5초 만에 잡혔다
- **핸드오프 파일명의 `b`/`c` 접미사는 같은 날 두 번 이상일 때만.** 날짜가 넘어가면 새 날짜를 쓴다
  (`generate_index.py`가 `sorted(reverse=True)[0]`으로 최신을 고르므로 `-2` 형태는 금지)
- 픽스처는 **회귀 확인용이지 신규 오탐 발굴용이 아니다.** DOCTYPE 공개식별자도 상수풀 `0x2F`도
  실측 리포트에서 처음 나왔다. 실소스 리포트를 눈으로 보는 일을 픽스처가 대체하지 못한다
