# 핸드오프 — AS-IS 경로/IP 치환 작업 (2026-07-25)

기존 단일 핸드오프 문서를 claude-workspace 형식으로 이관 + 이번 세션에서 경로 치환 자동화 완성.

## 프로젝트 맥락

- 레거시 EOS 소스 복구/이관 (eGovFrame, Ant/Ivy, LENA, 폐쇄망). AS-IS 경로(d:/)·IP → TO-BE 치환
- 대상 소스 약 30개, 소스별 1회 실행. 집(Maven/eGov 5.0.1 테스트)과 회사(레거시 Ant, 폐쇄망) 병행
- 환경 확정: Windows 서버, 드라이브 불변, **경로 구조만 변경, 매핑은 소스마다 다름** → 소스별 `path_mapping_<소스명>.dat` 운용

## 검증 이력 (PS 7.4, 컨테이너에서 실행 검증 완료)

- Replace-AsisPath: java `\\` 리터럴/properties `/`/xml `\` 스타일 보존, EUC-KR 한글 파일 치환 후 디코딩 정상, `d:\eosdata`·`d:/eos.bak`·`forward:/` 오탐 없음, Apply 백업 md5 원본 일치, 재DryRun REPLACE 0건, ExcludeList 동작
- 개발 중 발견·수정한 버그: ① UNMAPPED 커버리지 판정(PS 배열 중첩) ② `Sort-Object -Unique`가 정렬키(길이) 기준 dedup → 같은 길이 NewPath 유실 ③ 폴더 제외 정규식 `\` 전용 → `[\\/]` 중립화(Find/Replace 동시) ④ RootList 폴더명 중복 시 증적 덮어쓰기
- Find v8: 단일/일괄, bak 파일·폴더 제외, 추가 패턴, 없는 소스 스킵, WEB-INF 단독 조사, 출력 폴더 자동 생성
- **회사 실전 첫 조사**: portal 45건 (FILE 34 / CLASS 6 / WAR 5). Category상 빌드산출물 39건 → 실 치환 대상은 src 6건 추정. CLASS 6건의 대응 java 존재 확인 필요(없으면 디컴파일 회부)

## 오늘 이해한 것 (개념 — 안정화되면 concepts/로 증류)

- 표준 흐름 순서 확정: **0. Find all(전수+유실탐지) → 1. 경로 매핑표(조사 결과가 재료) → 2. 경로 치환 → 3. IP 치환 → 4. 재빌드 → 5. Find build 0건 → 6. 파일 외**
- 조사는 전체(all), 치환은 텍스트만 — class/jar/war는 재빌드·재패키징으로 해소 (Replace 기본 ExcludeDirs가 이를 강제)
- **WEB-INF 단독 조사 시 -Scope src 금지** (classes 폴더 제외 때문에 WEB-INF\classes 놓침) — 실측 시연으로 확인
- exploded WEB-INF의 FILE 검출은 성격 판단: 빌드 재생성 사본이면 재빌드 해소, 직접 운영 배포본이면 그 자리 직접 치환(이때 Replace ExcludeDirs에서 classes 제외 필요)
- -ExcludeDirs 직접 지정 시 기본값 **대체**됨(추가 아님)
- `pwsh -File`은 배열 파라미터를 문자열로 뭉갬 — 콘솔/ISE에선 정상, 자동화 시 `-Command "& script -Param @(...)"` 사용
