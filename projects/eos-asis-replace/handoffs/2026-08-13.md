# 핸드오프 — MAR/EOS 한글 인코딩 (2026-08-13)

도구 전체를 `tools/` 트리로 정리하고, 그 과정에서 **판정 오탐 1건 + 잠재 버그 3건**을 잡았다.
진단 자체는 진도가 없었지만, 앞으로의 측정 결과를 신뢰할 근거가 생겼다.

## 오늘 확정한 것

### 컴파일 무혐의 — 11개 클래스 기준으로 재확인

8/12 판정은 **8개 클래스 / 리터럴 90개** 기준이었는데, 현재 트리는 **11개 / 152개**다.
근거가 1:1 대응하지 않아 다시 측정했다.

| 측정 | 결과 |
|---|---|
| `Scan-ClassFiles` (build\classes 11개) | 인코딩일치 8 / ASCII만 3 — **깨짐·손실 0건** |
| `Scan-JavaSources` (src 11개) | 전부 UTF-8/ASCII — **MS949 0 / BOM 0 / FFFD 0** |
| 빌드 시각 | 11개 전부 `2026-08-12 22:53:12` (초까지 동일) = **clean 전체 빌드** |

부분 빌드 가설도 배제됐다. **가설 3(런타임 경로) 결론은 그대로 유효하며 근거가 넓어졌다.**

### `InlineCheck` 깨짐은 오탐이었다 — 원인 확정

`lev1`이 `InlineCheck.class`를 `재컴파일(소스확인)` / `깨짐-NOTFOUND`로 잡았는데, 도구 결함이었다.

```powershell
# lev1 구 로직 (453행)
if ($L -match "[\u00A1-\u00FF]") { $restored = Restore-Latin1 $L }   # Latin-1 검사가 먼저
elseif ($L -match "[\uAC00-\uD7A3]") { ... }                          # 한글 검사가 나중
```

문제 리터럴은 `→ static final String 상수 변경 시 참조 클래스 전부 재컴파일·재배포 필요`.
**`·`(U+00B7)가 `\u00A1-\u00FF` 범위**라 한글인지 보기도 전에 깨짐으로 단정하고 역변환해 전부 `?`가 됐다.

8/12에 `Scan-ClassFiles`에 적용한 수정(한글 검사 우선 + 역변환 검증)이 `lev1`에는 빠져 있었다.
`Scan-ClassFiles` 주석에 **예시로 적어둔 바로 그 문자열**("재컴파일·재배포")이 실제로 오탐된 것이다.

`lev1`이 낸 4건 모두 오탐으로 정리된다:

| 대상 | 실제 |
|---|---|
| `InlineCheck` 깨짐 | 위 오탐. `ant inline-demo`용 인라이닝 증명 픽스처 |
| `Sales` 멤버명미발견 11건 | Lombok 생성 (`-SkipNameCheck`로 해소, 26→15건) |
| `Sales(id=`, `, productName=` | Lombok `toString()` 리터럴 |
| `CommExcelView`의 `unchecked` | `@SuppressWarnings` = RetentionPolicy.SOURCE라 class에 없는 게 정상 |

### MS949 이중해석은 아무 한글에서나 재현되지 않는다

`Test-ClassParser` 작성 중 실측으로 확인. 원문의 UTF-8 바이트열이 **우연히 유효한 MS949 시퀀스**여야 성립한다.

| 원문 | UTF-8 → MS949 | 재현 |
|---|---|---|
| 매출 / 목록 / 조회 / 코드 / 금액 | 留ㅼ텧 / 紐⑸줉 / 議고쉶 … | 가능 |
| 매출현황 / 한글 / 파일 / 현황 | 디코드 실패 | **불가** |

실무 함의: 현장에서 `깨짐(949이중)`이 잡히면 오히려 특이 케이스다.
주된 경로는 여전히 `Latin1(UTF8소스)` — **조용히 깨지는 유일한 경로가 ISO-8859-1**이라는 결론과 일치한다.

> 위 개념들은 `concepts/`로 증류 후보 (판정 순서 원칙 / 949 이중해석 성립 조건 / PS 위치 ≠ .NET 위치)

## 이어서 할 때 참고

- **PowerShell 위치 ≠ .NET 위치** — `New-Item`은 `Get-Location` 기준, `[System.IO.File]::Write*`는
  `[Environment]::CurrentDirectory`(프로세스 시작 폴더) 기준. `cd`를 따라오지 않는다.
  폴더에서 바로 PS를 열면 우연히 동작하고 `cd`로 들어가면 실패해서 재현이 들쭉날쭉하다.
  `-shl` byte 잘림과 같은 급의 함정 — RUNBOOK "알려진 함정" 표에 추가할 것
- 판정 순서는 **FFFD → 한글 → Latin-1**. 뒤집으면 `·` `é` `€`가 깨짐으로 오판된다
- 깨짐 판정은 문자 범위 추정이 아니라 **역변환 성립 + 길이 감소** 두 조건
- 이번 세션 작업 환경엔 PowerShell이 없어 **패치 전부 구문 검증 미실시**. 실기기 첫 실행 시 확인할 것
- 파서 4벌 중복이 원인인 사고가 이틀 연속 2건(8/12 `-shl`, 8/13 판정 순서).
  모듈화를 끝내지 않으면 3번째가 나온다
